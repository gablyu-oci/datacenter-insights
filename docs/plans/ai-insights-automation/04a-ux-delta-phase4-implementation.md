Move the existing CTA at `AIInsightsTab.tsx` lines 154-169 out of the title-stack and into the **top-right of the page header**, vertically centered against the title row. Remove the `c.brand.primary` background fill.

- **Default treatment (secondary):** 1px border in `color.border.default`, neutral fill `color.bg.surfaceAlt`, foreground `color.text.body`, `radius.md`, height 32px, padding 0 12px, Lucide `RefreshCw` icon (14px) before the label. Matches `04-ux.md` §3.5.

- **Loading label:** exact string `"Running..."`, disabled, icon spins per `04-ux.md` §3.5.

## 2. Auto-generated badge

When `GET /api/insights/latest` returns a session with `created_by == "scheduler"`, render a single-line badge in the header rail. When `created_by == "manual"` or unset, render nothing.

- **Copy (exact):** `"Auto-generated YYYY-MM-DD HH:mm UTC"` — substituting the session's `created_at` rendered in UTC, 24-hour, zero-padded. No relative time. No emoji. No trailing punctuation.
- **Placement:** in the header rail, immediately after the freshness line, **before** the source pill. Visual order top-to-bottom: title, freshness line, badge (if scheduler), then the pill row (source pill + ongoing chip). On narrow widths it wraps onto its own line; it never sits to the right of the Run-again button.
- **Visual treatment (plain language):** small caption-weight text on a muted chip background. Background `color.bg.surfaceAlt`, foreground `color.text.faint`, `typography.meta` size, padding `2px 8px`, `radius.pill`, no border, no icon. Read-only — not interactive, not focusable, not in tab order.
- **Accessibility:** decorative metadata, not a CTA. `role="note"` with `aria-label="Auto-generated by daily scheduler at YYYY-MM-DD HH:mm UTC"` for screen readers (the SR label expands the abbreviated visible form). Cursor default; no hover affordance.
- **Tokens:** none new. Reuses `bg.surfaceAlt`, `text.faint`, `radius.pill`, `typography.meta` from `04-ux.md` §7.1.

This badge is duplicative of the source-pill signal by design — the pill says "this came from the scheduler", the badge says "and here is exactly when". Karan asked for both.

## 3. No flash-of-empty during Run again

The current "Generate insights" click path clears the feed and re-streams from zero. That is wrong now that there is a persisted latest session worth preserving.

- **Behavior:** on Run-again click, the previously rendered InsightCards stay mounted, opacity 1.0, in-place. The Run-again button enters its loading state (`04-ux.md` §3.5). No skeleton renders. No spinner overlays the feed.
- **Swap point:** the prior cards are replaced **only** when the new session emits its first `InsightCompleteEvent` over SSE. At that moment the card list is replaced wholesale by the new session's first card; subsequent `InsightCompleteEvent`s append per existing streaming behavior.
- **Error path:** if the new session emits an error event before any `InsightCompleteEvent`, restore the prior cards exactly as they were (the implementation should hold the prior `latest` response in memory across the click; do not refetch). Show the existing manual-run-error toast from `04-ux.md` §5.7. Do not blank the feed at any point in this path.
- **Header during transition:** the freshness line and source pill update to `"Manual run · streaming"` per `04-ux.md` §4.2 step 8 the moment the session id is returned; only the body cards observe the swap-on-first-complete rule. The auto-generated badge from item 2 disappears as soon as the source flips to manual.
- **Accessibility:** when the swap happens, move focus nowhere; do not announce the swap (the streaming UI already announces individual insights via `aria-live="polite"` on the feed region — preserve that).
- **Tokens:** none new.

## 4. Failed-latest banner reuse with last-successful inline-meta

When `GET /api/insights/latest` returns `status == "failed"` **and** the response (or a follow-on call per architect's choice in `04-ux.md` §4.2 step 4) includes a prior succeeded session, render the stale banner from `04-ux.md` §3.4.1 unchanged, with one additive line.

- **Banner copy (top line, unchanged from §3.4.1):** `"Today's auto-run failed at HH:mm UTC — showing yesterday's insights."`
- **New inline-meta line, rendered immediately below the top line, same banner container:** exact string `"Last successful run: YYYY-MM-DD HH:mm UTC"`. Sentence case, no trailing punctuation, UTC.
- **Visual treatment:** same `bg.warningSubtle` container, same `semantic.warning` border, same `AlertTriangle` icon. The new line is `typography.meta` size, `color.text.caption`, no icon, indented to align with the body of the top line (not under the icon). Single line; truncate is not expected because the string is fixed-length.
- **CTAs:** unchanged from §3.4.1 — `"View error"` and `"Retry now"`, right-aligned on the top line.
- **Body below banner:** the prior successful session's full InsightCards render below, exactly per §3.4.1 — banner does not change card behavior.
- **Hard-error variant (no prior success):** `04-ux.md` §3.4.2 still applies unchanged. Do not add the "Last successful run" line when there is no last successful run.
- **Accessibility:** banner is `role="status"` per `04-ux.md` §6.3. The new meta line is part of the same banner region, so screen readers announce it once with the rest. No separate `aria-label`.
- **Tokens:** none new.

## 5. Default-load behavior summary

On AI Insights tab mount the client fires a single `GET /api/insights/latest`, renders the skeleton header and three skeleton InsightCards from `04-ux.md` §1.2 / §2.1 while the request is in flight, hydrates header and feed on a 200 response, and renders the cold-start empty state from `04-ux.md` §3.7 on 404. No SSE connection is opened on mount. The user does not click anything to see the latest auto-generated session. This is the entire interaction model for the default morning visit.
